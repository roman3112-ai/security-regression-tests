# security-regression-tests

Учебный проект по регрессионному тестированию безопасности. Делал, чтобы
разобраться, как на практике выглядят уязвимости из OWASP Top 10 и как их
закрывают — и чтобы закрытая дыра не открылась снова после следующего
рефакторинга.

Идея простая: на маленьком FastAPI-приложении каждый эндпоинт сделан в двух
версиях — намеренно **уязвимой** и **защищённой**. Набор pytest-тестов
доказывает две вещи:

1. уязвимая версия правда ломается предложенной атакой (иначе демонстрация
   нечестная);
2. защищённая версия эту же атаку отбивает — и продолжает отбивать после
   любых будущих изменений.

Второй пункт и есть смысл слова *регрессионный*: если кто-то потом случайно
вернёт уязвимый код (например, скопипастит старую версию функции), тест
упадёт и CI покраснеет. Так фикс не сгниёт незаметно.

> ⚠️ Код в `app/insecure.py` сломан намеренно, в учебных целях, и работает
> только со своей же одноразовой in-memory базой. Не тащите эти паттерны в
> реальные проекты — оттуда брать пример нужно с `app/secure.py`.

## Что проверяется (OWASP Top 10, 2021)

| # | Категория | Эндпоинт | Как сломано | Как исправлено |
|---|-----------|----------|--------------|-----------------|
| A01 | Broken Access Control (IDOR) | `GET /notes/{id}` | отдаёт любую заметку по id | проверка владельца |
| A02 | Cryptographic Failures | логин / хранение | пароли в открытом виде | PBKDF2 + сравнение за постоянное время |
| A03 | Injection (SQLi) | `POST /login` | SQL собирается из строк | параметризованный запрос |
| A03 | Cross-Site Scripting | `GET /search` | ввод отражается без экранирования | HTML-экранирование |

## Структура

```
app/
  db.py          # одноразовая in-memory SQLite, заполняется детерминированно
  insecure.py    # уязвимые эндпоинты (антипаттерны помечены комментариями)
  secure.py      # защищённые эндпоинты (на них и стоит учиться)
  main.py        # точка входа uvicorn -> поднимает защищённое приложение
tests/
  test_sql_injection.py
  test_broken_access_control.py
  test_xss.py
  test_password_storage.py
```

## Быстрый старт

```bash
pip install -r requirements.txt
pytest            # прогнать регрессионные тесты
ruff check .      # линтер
```

Поднять защищённое приложение и потыкать его через Swagger UI:

```bash
uvicorn app.main:app --reload
# http://127.0.0.1:8000/docs
```

Или через Docker:

```bash
docker build -t secreg .
docker run -p 8000:8000 secreg
```

## Как читать тесты

В каждом файле с тестами есть пара: `*_is_vulnerable` / `*_allows_*`
(фиксирует уязвимость в insecure-версии) и `*_rejects_*` / `*_blocks_*`
(регрессионная защита на secure-версии). Проще всего начать с
`test_sql_injection.py` — payload-тавтология `' OR '1'='1` это классика
жанра.
